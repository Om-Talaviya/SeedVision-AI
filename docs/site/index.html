Deep Learning Applications · Computer Vision · Agricultural Quality

Explainable deep learning for agricultural seed quality grading

SeedVision AI inspects chickpea (Cicer arietinum L.) seed imagery and assigns each sample one of four visual quality classes — with a Grad-CAM saliency overlay showing which pixels influenced the decision. Two architectures, one leakage-resistant evaluation protocol, and a first-class honesty contract about what optics can and cannot measure.

What is — and is not — established

Benchmark data is synthetic

All 240 training images are procedurally generated verification fixtures (data/provenance.json), not field photographs. The perfect scores reported here are a software-verification result, not an agronomic accuracy claim.

Real-world validation is pending

Evaluation artifacts carry is_real_world_validated: false and evaluation_type: synthetic_pipeline_verification. A certified field benchmark has not been run.

Real photographs are unreviewed

Exactly 6 real photographs (2 specimens × 3 angles) exist. All remain unlabeled and pending; zero have been approved, and none were used to train the models.

Optics ≠ physiology

The system assesses visible surface morphology only. It cannot measure germination rate, embryo vitality, moisture, or pathogen viability — those require laboratory assays.

01 — Project

A scientific-grade computer vision pipeline

Manual seed inspection is slow, subjective, and inconsistent between graders. SeedVision AI is a production-structured reference implementation that replaces ad-hoc scripting with a modular, reproducible, and explainable pipeline — while being explicit about its scientific boundary.

The problem

  • Manual visual grading is subjective and varies between inspectors.
  • Hand sorting cannot scale to high-throughput lot screening.
  • Mechanical damage and surface defects are easy to miss under inconsistent lighting.
  • Black-box "AI graders" provide no auditable evidence for their decisions.

The approach

  • Two CNN architectures trained and compared under one identical protocol.
  • Deterministic preprocessing with train-time augmentation and eval-time normalization.
  • Leakage-resistant, class-stratified group splits keyed on physical seed identity.
  • Grad-CAM explainability surfaced alongside every prediction, not hidden in a submenu.

Four quality classes

  • sound_healthy Intact testa, uniform colour.
  • discolored_spotted Necrotic spots, staining.
  • broken_cracked Fractures, chips, splits.
  • shrivelled_damaged Wrinkling, shrunken form.

A fifth staging-only state, pending_review, exists for unlabeled real intake — it is never a classifier output.

02 — Capabilities

Engineered features

Each subsystem is a small, contract-bound module with tests around its boundary.

◲

Dual architectures

A from-scratch SeedNet-Baseline CNN and an ImageNet-pretrained MobileNetV2 transfer model, built through one factory interface.

◎

Grad-CAM explainability

Gradient-weighted activation mapping with strict hook lifecycle management (context manager) to prevent memory leaks.

⧉

Leakage-resistant splits

Class-stratified group splitting keeps every physical seed entity atomic within a single partition.

⎔

Input validation

Uploads are screened for size, MIME type, and minimum dimensions before a tensor is ever built.

∿

Full evaluation suite

Accuracy, macro precision/recall/F1, per-class metrics, confusion matrices, ECE calibration, and CPU latency/throughput.

⚠

Uncertainty surfacing

Low-confidence and out-of-distribution inputs are flagged with an actionable reason instead of a silent guess.

⊕

Advisory review assistant

Optional, default-deny review aid for real intake — it can only recommend; a human always decides.

⚙

Reproducible & tested

Master seed 42, YAML config cascade, atomic checkpoints, and a 99-case pytest suite.

SeedNet-Baseline

Custom CNN · edge-optimised

Four conv blocks (3→32→64→128→256), LeakyReLU, adaptive average pooling to 256-d, dropout 0.35, head to 4 classes. 2.3× faster and 5.2× more compact — the throughput pick for high-speed sorting.

MobileNetV2-Transfer

Transfer learning · ImageNet-pretrained

Inverted residual blocks with depthwise separable convolutions, custom classification head with dropout 0.30 and a reduced fine-tuning learning rate (3×10⁻⁴).

05 — Explainability

Grad-CAM saliency

Predictions arrive with their evidence. Grad-CAM pools the gradient of the predicted class score over the final convolutional feature map, rectifies it with ReLU, normalises it, and blends the result over the input as an alpha overlay.

Original specimen

Cropped RGB view of the seed under analysis.

Activation heatmap

Jet-colormapped saliency normalised to [0, 1] at the last conv layer.

Blended overlay

45% alpha blend highlighting the fracture or lesion region.

Weights αkc = (1/Z) Σi,j ∂yc / ∂Akij
Map Lc = ReLU( Σk αkc Ak )
Overlay α·HeatmapRGB + (1−α)·ImageRGB
!
Associative, not causal. Grad-CAM shows regions whose activations correlate with the output logit. Heatmaps are computed at a coarse feature map (e.g. 4×4–8×8) and upscaled bilinearly, so fine crack edges appear diffused.

06 — Real-data workflow

Advisory review assistant

When real photographs enter staging they are pending_review and contribute nothing to training until a human decides. The review assistant can recommend, but it can never approve.

Default-deny by construction

Auto-approval is hard-disabled (AUTO_APPROVAL_ENABLED = False). The recommendation chain fails closed.

Quality screening

Blur (Laplacian variance), perceptual near-duplicate hashing, and checkpoint-compatibility checks surface advisories.

Human label preserved

A reviewer's decision always wins; assistance never overwrites a human grade or writes to the manifest.

Read-only staging

The staging manifest stays pending; the assistant emits an advisory sidecar only.

09 — Boundaries

Scientific limitations

The most important section on this page. Computer vision reads visible morphology; it cannot read biochemistry.

Which properties are detectable by computer vision versus which require laboratory assays
Property Detectable by SeedVision AI Requires laboratory assay
External testa integrityYes—
Surface pigmentationYes—
Gross morphologyYes—
Insect boreholesYes—
Germination rateNoGermination blotter test
Embryo vitalityNoTetrazolium (TZ) staining
Moisture contentNoOven-dry / NIR meter
Pathogen viabilityNoAgar culture / PCR
Lot certificationNoOfficial seed agency (ISTA/AOSCA)
  • Species-restricted. Trained for chickpea only; other species produce out-of-distribution errors.
  • Lighting-sensitive. Coloured light, harsh shadows, or textured backgrounds degrade accuracy.
  • Coarse heatmaps. Grad-CAM resolution limits localisation of fine cracks.
  • Never certification. Outputs are never official seed testing or safety guarantees.

10 — Run it locally

Setup & links

Clone the repository and launch the full Streamlit dashboard to run the real models.

Quick start

git clone https://github.com/Om-Talaviya/SeedVision-AI.git
cd SeedVision-AI
python -m venv .venv
.venv\Scripts\activate        # Windows
python -m pip install -r requirements.txt
python scripts/prepare_dataset.py
python scripts/train.py --config configs/transfer_learning.yaml
streamlit run app.py          # http://localhost:8501

Requires Python 3.10–3.13 and PyTorch 2.2+. CPU is the default; CUDA is auto-detected.

Evaluate a checkpoint

python scripts/evaluate.py \
  --checkpoint artifacts/checkpoints/best_SeedNet-Baseline.pt

python scripts/evaluate.py \
  --checkpoint artifacts/checkpoints/best_MobileNetV2-Transfer.pt
